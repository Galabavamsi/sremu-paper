Latexmk is a Perl script: run the build from Git Bash (its `/usr/bin/perl`) or with another
Perl on `PATH`; MiKTeX's own launcher fails without one.

Page budget: the main text (Sections I-X and the back matter) and the references it cites end
on page 14 (page fit of 2026-10-12: Sections I-X end on p. 12, references [1]-[76] on p. 14).
References cited only in the appendices are numbered after them and print next, before
Appendix A; they may run onto p. 15. Detail moved for length sits in Appendices A-F under the
same claim markers (claims.yaml `where` lists both files). Caveats stay in the main text even
when their numbers moved (e.g. C-EB-SERVED: Section VII-A keeps the conclusion, Section VI and
Appendix F the numbers).

Result macros and generated tables (run after the junit is in place and after the figure

```powershell
D:\projects\ris\sremu\.venv\Scripts\python.exe figures\src\f03_aperture_tang.py   # and f04 ... f12
D:\projects\ris\sremu\.venv\Scripts\python.exe tools\gen_results.py              # results.json, generated result tables
```

`gen_results.py` reads only committed result files (sremu `validation/*/results/<run>`,
`paper/sweeps/results/*`, the pinned junit, the figure data) and checks every value against
its `max_chars` budget; `--check` compares with the committed outputs. Figure scripts follow
the registry contract (`--profile --figure --content-key`), fit the PDF to the column or text
width so that LaTeX includes it at scale 1 (fonts >= 8 pt, Type 42), and record inputs with
sha256 and data classes in `figures/data/<Fid>.meta.json`.

`latexmk` and `pdflatex` come from MiKTeX (its "unsupported Windows" banner is harmless).
`--no-latex` runs every step except LaTeX (including the TikZ diagrams). `PROFILE=fast|full`
is passed to figure scripts. Code values (`code` macros) and the API table need an importable
sremu (the sremu venv); without one, draft builds keep placeholders / the committed table and
warn, final builds refuse.

The final mode refuses unless:

1. `sremu.lock` holds a 40-hex commit equal to the sremu HEAD, both trees are clean, and
   the interpreter imports `sremu` from that checkout;
2. every id of `gates.yaml` (GATE-PHY, GATE-RT; DESIGN 10.13) passes in the pinned junit,
   and PH-17...PH-22 pass once per backend (`[numpy_ref]` and `[numba_cpu]` in the test ids).
   Only implementation tests count (not `tests/oracles` self-tests, not golden-harness tests
   without `sremu` in the name), and a skipped or xfailed matching test keeps an id red.
   Every junit file must record the commit it was produced at: testsuite properties
   `sremu_commit` (= `sremu.lock`) and `sremu_dirty` (= `false`), or a sidecar
   `<junit stem>.meta.json` with the same keys. A junit of unknown or other provenance is
   refused, and `check_claims --mode final` applies the same rule to claim evidence;
3. every figure F1-F12 of `figures/registry.yaml` is placed once in the sections with its
   registered width, label `fig:<Fid>` and every data class in the caption, and is current
   (content key = sha256 of sremu commit, sweep spec, input hashes and script; the meta
   carries the registry's data classes and the commit);
4. `generated/numbers.tex` has no placeholder, and no `\sremustub` remains;
5. `check_claims` (final), `check_refs` and `check_arxiv` pass; after LaTeX, `main.bbl` exists
   and no citation or reference is undefined.

## arXiv package

`tools/make_arxiv_package.py` turns a completed build into the source upload. It runs offline
(standard library; pdflatex for the check, pdftotext if present) and never runs git.

```powershell
# after a final build (generated/buildmode.tex says \sremudraftfalse); refuses anything else
D:\projects\ris\sremu\.venv\Scripts\python.exe tools\make_arxiv_package.py
# trial run on a draft build: temp directory, everything labelled DRAFT-NOT-FOR-SUBMISSION
D:\projects\ris\sremu\.venv\Scripts\python.exe tools\make_arxiv_package.py --mode draft-test
```

- **Files.** `main.tex` and what it reaches: `\input`/`\include`/`\InputIfFileExists`
  (recursively, the generated files included), the figures of `\includegraphics` and of the
  macros that wrap it (`\sremufigure`), local `.cls`/`.sty` files (none: `IEEEtran.cls` is the
  stock V1.8b of the TeX distribution, which arXiv has), and `main.bbl`. `refs.bib` is left out
  (arXiv uses the `.bbl`; it does not run BibTeX reliably). The list must equal the paper files
  that the build read (`main.fls`), and every file must have the checksum that latexmk recorded
  for `main.pdf` (`main.fdb_latexmk`), so a stale build is refused: rebuild first.
- **Stripping** (`.tex` only; `.bbl` copied, line ends normalized): comment lines are dropped,
  `code % text` becomes `code %` (the `%` keeps suppressing the end-of-line space), `\%`,
  `\verb`, verbatim environments and URL arguments are kept; the `\claim{ID}` markers (the only
  macro of `sremu-macros.tex` that prints nothing) are removed, as `{}` wherever plain removal
  would change TeX's spaces; definitions of internal macros that nothing uses any more
  (`\claim`, and `\sremustub`/`\sremuPlaceholder` once a final build has none) are dropped.
  `main.tex` gets `\pdfoutput=1` as its first line (arXiv's cue for pdfLaTeX).
- **Verification.** The package is compiled alone in a temporary directory with pdflatex (two
  runs, more while LaTeX asks; no BibTeX) and must give exit 0, no undefined reference or
  citation, the page count and the text (pdftotext) of `main.pdf`, and the same rendered
  content (every page, font and figure stream of the two PDFs, decompressed). No packaged file
  may contain `sremustub`, `TODO`, `\claim{`, `Planned]` or a local absolute path (in a
  draft-test the draft's stubs are warnings), and the package must stay below arXiv's 50 MB.
  The archive is written only when every check passes.
- **Output** (final: `arxiv/`, gitignored; `--out DIR` elsewhere): `source/` (the tree),
  `sremu-arxiv.tar.gz` (upload this; reproducible: the same build gives the same bytes),
  `abstract.txt` (`check_arxiv.py --emit-plain`, for the form), `metadata.txt` (title, authors,
  primary eess.SP, cross-list cs.NI, comments line "N pages, F figures, T tables") and
  `verification.txt`.

After the final build: run the tool, upload `sremu-arxiv.tar.gz`, paste `abstract.txt` and the
fields of `metadata.txt` into the form, and check arXiv's own PDF against `main.pdf` before
announcing (arXiv's TeX Live may differ from MiKTeX in package versions).

## Rules (DESIGN 1.6, 13.6)

- **Code numbers.** A constant or default of the sremu code that the text quotes (frame header
  size, message caps, page limits, interpolation target, FD filter rows, ...) is a `code`
  macro: `source: {type: code, id: <sremu module>, expr: <expression>, fmt: <format>}`.
  `tools/resolve_code_numbers.py` evaluates it in the installed (final build: the pinned)
  sremu and the values land in `generated/code_values.json` and `generated/numbers.tex`, so
  the text cannot drift from the code (a test compares them with a fresh resolution).
- **Numbers.** Every number in the text is a macro from `numbers.yaml` or a literature
  number in a cited sentence/table row; a citation does not cover a sentence about sremu
  itself. Numbers glued to units (`5.2ms`, `3x`, `1e-3`) count as numbers; in math,
  decimals, integers >= 2 after a relation (`N = 1024`) and integers with a unit are
  flagged. A fixed `value` is allowed only for definitions (DESIGN 12.1),
  dataset facts and third-party numbers: source type `reported` (data class REPORTED) names
  the BibTeX keys in `cite`, and `check_claims.py` requires each sentence or table row that
  uses the macro to cite all of them. Text macros carry a `max_chars` budget; `check_arxiv.py` bounds the abstract
  (<= 1920 characters, <= 200 words) with every placeholder at its budget.
- **Banned words** ("first", "only", "compliant", "digital twin", "accurately replicates",
  "no loss of functionality") need a claim with a `banned_word_uses` entry; "real-time" is
  allowed only in "real-time factor", "hard/soft real time" and "non-real-time".
- **Claims** are pending until their tests pass in the pinned junit, their figures exist and
  their human gates are closed. Draft builds list pending claims; final builds refuse them.
  Evidence is a spec id (`test:RT-05`) or, for capabilities without one, a sremu test file or
  test (`pytest:tests/unit/test_wp9_env.py[::test_name]`). Code identifiers in `	exttt{}`
  are names, not prose: the banned-word and real-time rules skip them (numbers still count).
- **References.** Add an entry only with a primary-record check: a row in
  `refs_verification.md` (origin `new`) and, ideally, `python tools/verify_refs_online.py
  --keys <key>` (network). Every entry needs a doi, an arXiv eprint or an official URL;
  printed fields may not contain bare URLs.
- **Verification vs validation.** MATLAB agreement is code-to-code; digitized data is DIG
  with its uncertainty; the lab comparison is a "consistency check under geometric
  uncertainty" unless the lab supplies the geometry (H-1).
- **AI disclosure.** The acknowledgment (`sections/back_matter.tex`) holds a planned-content
  stub for the generative-AI disclosure, which the authors write (IEEE requires it in the
  acknowledgments; arXiv asks authors to report significant use of text-generating tools); a
  final build refuses the stub.
- **Availability.** `availability.yaml` holds the release status and the licence, repository
  URL, archive DOI and data DOI of "Code and Data Availability". With `status: conditional`
  the section prints the conditional statement and no field (the macros expand to
  `\sremuUnreleased`, which stops a build that prints one); with `status: released` every field
  is printed and PENDING fields stay placeholders (final build refuses).
